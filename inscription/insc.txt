To perform an NFT inscription on btc ord , "ord" it's needed.

the ord client needs to be run against the testnet in order for it to work.

https://ordtutorial.vercel.app/ordtestnet

ord --testnet4 \
  --bitcoin-data-dir "/Users/mimmo/Library/Application Support/Bitcoin" \
  --index-runes \
  server


leave this running on a shell.
(might look stuck at indexing blocks near the end, but it actually finishes and it is actively listening on the port)

Looks like that there is a bug in newer versions of btc core that leads inscribe command to fail:
Basically performing this command leads to store a safety key that helps to recover the funds if the transaction is not succesfull.
This key storing process is just an "import descriptor" bitcoin core call that can fail, resulting in the previous error.
Inscribing with no backup means to be screwed in the case the transaction is not mined.
