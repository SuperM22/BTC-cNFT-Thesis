2. Protocol setup

The seller will compute the proof containing:

struct Journal {
    hk: [u8; 32],
    himg: [u8; 32],
    nonce: [u8; 12],
    stride: u32,
    down_w: u32,
    down_h: u32,
    downgraded: Vec<u8>,
    ciphertext: Vec<u8>,
}

3. advertising

Somehow the seller shows the downgraded proof to some buyer.
the buyer will verify the proof.

4. verification
(packet for the verifier should be: proof.bin guest.bin ?verifiercode)

As the R0 documentation says, the verifier will be provided with the elf file of the project.
this can be found at sha-demo/target/riscv-guest/methods/sha_guest/riscv32im-risc0-zkvm-elf/release
from this file the verifier will extract the image id of the program and then check the proof against it.

Actually is not the elf file but the binary.

5. buyer creates the p2wsh with the H(k) derived from the proof


6. The seller redeems the funds by revealing k on chain

7. the buyer decrypts the cypher text via k and the nonce
